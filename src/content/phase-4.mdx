## TF2 — The Transform Framework
### The "Why" & The "How" (Coordinate Frames & The TF Tree)

A robot is a collection of rigid bodies: the chassis, a tilted LiDAR, a camera on a gimbal, a manipulator arm. Every sensor reports data in **its own local frame**. The LiDAR reports a point at `(2.0, 0, 0)` — but *2.0 meters from where?* From the LiDAR's origin, not the robot's center.

**TF2** solves this by maintaining a live **tree of coordinate transforms**. Any node can ask: *"Where is this LiDAR point in the `map` frame?"* — and TF2 chains the transforms (`lidar_link` → `base_link` → `odom` → `map`) to compute the answer, with correct time interpolation.

### The Standard Frame Hierarchy

Every ROS 2 mobile robot uses this canonical frame tree:

```
map ── odom ── base_link ──┬── base_footprint
                            ├── lidar_link
                            ├── camera_link
                            └── imu_link
```

| Frame | Authority | Purpose |
|-------|-----------|---------|
| `map` | SLAM / global localizer | Global fixed frame, drift-free but discrete |
| `odom` | Wheel odometry / EKF | Continuous, smooth, but drifts over time |
| `base_link` | Robot URDF | Robot body center |
| `*_link` | URDF / static broadcasters | Individual sensor mounts |

<Callout type="why" title="The Why — Why Split map and odom?">
`odom` is smooth (updated at 100Hz from wheel encoders) but drifts. `map` is drift-free (corrected by SLAM) but jumps discontinuously when a loop closure happens. By splitting them, your local planner uses `odom` for smooth control, while the global planner uses `map` for accuracy. The TF tree lets both coexist.
</Callout>

### Implementation — The Static Broadcaster

A static transform never changes (e.g. the LiDAR is bolted 20cm forward of `base_link`). Use `static_transform_publisher`:

<TerminalBlock title="bash">
{`# Publish a static transform: base_link -> lidar_link
# Arguments: x y z yaw pitch roll parent child
ros2 run tf2_ros static_transform_publisher 0.2 0 0.15 0 0 0 base_link lidar_link`}
</TerminalBlock>

### Implementation — Dynamic Broadcaster & Listener

For transforms that change over time (e.g. `odom` → `base_link` updated by the EKF), you publish to `/tf` dynamically.

<CodeBlock
  title="src/odom_broadcaster.cpp"
  cpp={`#include "rclcpp/rclcpp.hpp"
#include "tf2_ros/transform_broadcaster.h"
#include "geometry_msgs/msg/transform_stamped.hpp"
#include "nav_msgs/msg/odometry.hpp"

class OdomBroadcaster : public rclcpp::Node {
public:
  OdomBroadcaster() : Node("odom_broadcaster") {
    tf_broadcaster_ = std::make_unique<tf2_ros::TransformBroadcaster>(this);
    sub_ = this->create_subscription<nav_msgs::msg::Odometry>(
      "/odom", 10,
      std::bind(&OdomBroadcaster::on_odom, this, std::placeholders::_1));
  }
private:
  void on_odom(const nav_msgs::msg::Odometry::SharedPtr msg) {
    geometry_msgs::msg::TransformStamped t;
    t.header.stamp = msg->header.stamp;
    t.header.frame_id = "odom";
    t.child_frame_id = "base_link";
    t.transform.translation.x = msg->pose.pose.position.x;
    t.transform.translation.y = msg->pose.pose.position.y;
    t.transform.rotation = msg->pose.pose.orientation;
    tf_broadcaster_->sendTransform(t);
  }
  std::unique_ptr<tf2_ros::TransformBroadcaster> tf_broadcaster_;
  rclcpp::Subscription<nav_msgs::msg::Odometry>::SharedPtr sub_;
};

int main(int argc, char ** argv) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<OdomBroadcaster>());
  rclcpp::shutdown();
}`}
  python={`import rclpy
from rclpy.node import Node
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped
from nav_msgs.msg import Odometry

class OdomBroadcaster(Node):
    def __init__(self):
        super().__init__('odom_broadcaster')
        self.tf_broadcaster = TransformBroadcaster(self)
        self.sub = self.create_subscription(
            Odometry, '/odom', self._on_odom, 10)

    def _on_odom(self, msg):
        t = TransformStamped()
        t.header.stamp = msg.header.stamp
        t.header.frame_id = 'odom'
        t.child_frame_id = 'base_link'
        t.transform.translation.x = msg.pose.pose.position.x
        t.transform.translation.y = msg.pose.pose.position.y
        t.transform.rotation = msg.pose.pose.orientation
        self.tf_broadcaster.sendTransform(t)

def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(OdomBroadcaster())
    rclpy.shutdown()`}

<Callout type="pitfall" title="CRITICAL Pitfall — The Broken Tree">
If TF2 returns *"Could not find a connection between base_link and map"*, your tree is **broken** — a parent-child link is missing somewhere. Every frame must have exactly **one parent** in the tree. A disconnected subtree is the #1 cause of "TF extrapolation into past" errors in Nav2.
</Callout>

<Callout type="best-practice" title="Best Practice — Publish at Sensor Rate">
Broadcast dynamic transforms at the **rate of the source sensor** (e.g. publish `odom`→`base_link` at the EKF output rate, typically 30-50Hz). TF2 interpolates between stamps, but cannot extrapolate more than the `cache_time` (default 10s). Stale transforms cause silent Nav2 failures.
</Callout>
